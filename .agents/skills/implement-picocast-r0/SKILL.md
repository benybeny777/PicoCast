# Rust基盤と旧環境を移行する

1. `HANDOFF.md` → `DESIGN_implementation_plan.md` §5 → `DESIGN_rust_rewrite.md`・`docs/r0-foundation.md`・対象WPの正本の順に読み、現在の差分と照合する。販売機能とPythonの新規機能は作らない。既存未コミット差分は保持する。
2. Rustの所有境界は `crates/picocast-core`、`crates/picocast-store`、`xtask` に分ける。チャンネルを `ChannelId` で明示し、設定・時刻・HTTP・プロセス・書込み・DBの持ち主を通す。禁止を解除して通すのではなく、共通部品へ集約する。
3. 修正中は確実に必要な単体テストのみ実行する。変更がまとまった最後に、このPCで `cargo fmt --all` と `cargo xtask verify` を実行する。依存は `Cargo.lock` の `--locked` を使う。利用者指示（2026-10-16）によりGitHub Actionsでの検証は禁止し、無料枠を理由に有効化しない。Windows実機とmacOSの未確認を分けて記録する。
4. 改名と旧環境移行の前に、自動運用、実プロセス、metadataの未完了記録を照合する。古い `running` 表示だけで活動中と断定せず、PID・時刻・プロセスを確認する。履歴を消したり有料処理を自動再実行したりしない。
5. マスターキーと設定・metadata DBをリポジトリ外へ退避する。DBはSQLiteのオンラインバックアップを使い、WAL込みで整合性を確認する。未コミット差分も退避し、秘密値は画面・ログ・Gitへ出さない。
6. 実行中のCodexが使うフォルダを移すときは、参照先の更新とセッション再開を含む `DESIGN_rust_rewrite.md` §2.2 を満たす。旧名の別フォルダや新しいリポジトリを勝手に作って分岐させない。操作できないアプリ設定は未完了として正確に記録する。
   - フォルダだけの改名は `scripts/rename-picocast-folder.ps1` を使う。`-CheckOnly` で事前確認し、実行時は関連アプリを閉じた別のPowerShellから起動する。スクリプトは改名元・改名先・プロセスを検査し、改名後にGit worktreeを修復する。改名済みなら繰り返さない。環境切替はWP-R0-2として現位置で行う。
7. 保管用の `legacy/` は作らない。Python版は切り替えまで現位置で使い、R5の切り替え検証後に棚卸し表で不要と確認したコードを削除する。必要な旧コードはGit履歴から参照する。DB・生成物・認証情報などGit管理外のデータは削除対象に含めない。
8. Python 3.12の環境を作る前に3.11環境を退避する。`uv sync --locked --group build` で再現する。リポジトリ直下の起動スクリプトとREADMEをuv前提に合わせる。外部のVOICEVOX・SD・Ollama環境は変更しない。
9. 全体の確認は環境切替後に1回へまとめる。既存データを変更しないテストとサンプル確認を使い、必要な外部サービスが無い場合は実確認と扱わない。検証できるまで旧環境を消さない。
10. 1 WPごとに専用ブランチとPRを作り、関連差分だけをコミット・pushする。土台が未マージならそのブランチをbaseにし、PR本文に対象WP・詳細設計・検証・未確認を記載する。明示指示なしにマージしない。HANDOFFは未マージ作業・残り・再開方法に絞り、完了したWPは実装計画へ記録する。
