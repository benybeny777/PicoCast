# AI 費用台帳 API

`picocast_store::ai_cost` は既存の `cost_ledger` を正本とし、AI 送信の予約・実績・不明な請求をチャンネルごとに管理する。別のメモリ台帳は持たない。予算は呼出側が設定・`AutopilotPolicy` などの正本から取得し、呼出ごとに明示注入する。手動送信にも使うため、自動運用の有効状態を暗黙に要求しない。

## 予約

`Store::reserve_ai_cost(&AiCostReservation)` は登録済みで未アーカイブの `ChannelId`、一意な `request_id`、`UtcDay`、UTC の `at`、日次金額・トークン予算、送信の最大費用と入出力トークン上限を受け取る。金額単位は整数の micros。最大費用が不明な `None` は拒否し、確実に無料の場合の `Some(0)` は許可する。

日付は `UtcDay::parse` または `UtcDay::from_timestamp` で作る。予約日と `at` の UTC 日付が異なる指定は拒否する。実績を後日確定しても予約日の集計に含める。

即時トランザクション内で消費済みと予約中の合計を確認して予約を保存するため、別接続から同時に要求しても日次予算を超えて予約できない。既存の同一チャンネル・同一リクエストは拒否する。予約済みの ID を再利用して再送許可を得ることはできない。

## 確定

`Store::settle_ai_cost(channel, request_id, settlement)` は元のチャンネルと予約を指定する。

| 状態 | 保存する内容 | 予約の扱い |
|---|---|---|
| `Succeeded` | 確定費用・入力トークン・出力トークン | 実績へ置換 |
| `Failed` | 課金されなかったことが確かな失敗コード、費用 0 | 解放 |
| `Unknown` | 到達・課金結果が不明な失敗コード | 金額・最大入出力トークンを保持 |

接続断、タイムアウト、送信後の取消、使用量欠落などは `Unknown` とする。`Failed` に正の費用だけを渡して使用量不明の予約を解放することはできない。不明状態からは、確認済みの実績または課金なしの結果で確定できるが、その間の自動再送は許可されない。

同じ確定内容の再適用は成功する。確定済み結果と異なる内容への変更は拒否する。実績が予約費用・入力・出力のいずれかの上限を超えた場合、過少計上を防ぐため実績を先に保存し、`E-AI-USAGE` を返す。

送信中にチャンネルがアーカイブされた場合も、既存予約の実績確定と集計は許可する。新規予約は拒否する。通常の typed repository のアーカイブ境界は変更しない。

## 集計と保存形式

`Store::ai_cost_totals(channel, day)` は `charged_micros`、`held_micros`、`input_tokens`、`output_tokens`、`held_tokens`、`unpriced_entries` を返す。予約中と不明状態では最大入力・出力の合計を `held_tokens` に含める。

状態は `cost_ledger.units_json.ai_cost` の版付きメタデータに保存する。既存の AI 以外の台帳行も、既知費用は金額集計に含める。費用不明の既存行がある日は追加予約を拒否する。JSON の破損、不整合、整数の桁あふれは停止し、空値や無料扱いで継続しない。

`E-AI-BUDGET` は予算・上限・日付、`E-AI-RESERVATION` は予約の識別と状態遷移、`E-AI-USAGE` は実績や保存メタデータの不整合に使う。エラーには対処手順を付け、台本・認証情報などを台帳メタデータへ保存しない。

検証は一時 DB の限定テストで、並行した金額・トークン予約、再起動後の不明予約保持、同一結果の再確定、チャンネル・日付境界、未知費用、超過実績の保存、アーカイブ中の実績確定を確認する。実 DB と有料 API は使用しない。
