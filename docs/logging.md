# Rust共通ログと異常終了記録

WP-R0-3。実装は `picocast_core::logging`、書込みの持ち主は `fsutil`。本番のTauri接続はWP-R4-1で行う。

## 起動と終了

OSのデータ保存先を `settings::windows_storage_environment()` から受け取り、通常版または開発版の管理ルートを渡す。`Logging::open` へ役割（`App` / `Tick`）、型付き設定レジストリ、秘密値の伏せ字登録を明示注入する。登録値は `logging::setting_definitions()` を設定正本に組み込み、利用時に読み直す。

アプリ起動時に `install_global()` を1度呼ぶ。ジョブは `step_span(&ChannelId, job_id, step)` の文脈で実行し、非同期・別スレッドへ文脈とDispatchを伝搬する。各ジョブ境界と正常終了前に `check_health()` を呼び、ログ失敗のまま処理を成功扱いにしない。正常終了時だけ `shutdown()` でセッションマーカーを空にする。

## 保存・上限

- JSONLは管理ルート配下の `logs/app/` と `logs/tick/` に分け、UTCの日付と連番で保存する。
- `log_retention_days` は既定30日、`log_max_bytes` は既定256MiB。総容量を2役割へ均等配分するため各役割は128MiB以下となる。設定変更は次のイベントまたはメンテナンスから反映する。
- 日付・容量の上限に達したら古い管理ログから削除する。同日のログも分割し、直近のイベントを残す。1イベントだけで割当容量を超える場合は設定エラーで停止する。
- 完了ジョブの詳細ログは `job-YYYY-MM-DD-識別子.jsonl`（日付は完了日）の命名で受け取り、`job_log_compress_days`（既定90日）後にgzip圧縮する。未完了ログはこの命名にしない。ジョブ側の接続はWP-R2-10で行う。
- 圧縮は一時ファイルの同期と排他的な確定に成功してから元ファイルを削除する。日付・連番の規則に合わない利用者ファイルは削除しない。symlinkやディレクトリをログとして追跡しない。

## 異常終了と秘密値

同じ役割の二重起動はOSファイルロックで拒否する。パニック時は安定した通知を `crash.json` に保存し、内部トレースはデバッグログだけへ残す。パニック本文は秘密値を含み得るため保存しない。強制終了は次回起動時に残存マーカーから検出する。`pending_crash()` は通知を返し、表示・確認後だけ `acknowledge_crash()` で消す。自動投稿やジョブ再送は行わない。画面通知の接続はWP-R4で行う。

APIキー・トークンなどは呼出元からログへ渡さない。追加防御として、秘密値を `SecretRedactor::register` へ登録し、spanとイベントの両方を出力直前に伏せる。秘密値を示すフィールド名は値の型にかかわらず伏せる。

ログ内部のI/O失敗を同じsinkへ再出力すると再帰するため、失敗を保持して `check_health()` と終了処理から安定したエラーを返す。新コードは `E-LOG-CONFIG` / `E-LOG-IO` / `E-LOG-LOCK` / `E-LOG-INIT` / `E-LOG-CRASH`。通知には内部トレースや例外本文を含めない。
