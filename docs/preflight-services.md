# 事前点検と外部サービスの所有

WP-R2-11のRust API。`preflight::Preflight`へ対象ChannelId、工程に必要な依存集合、任意の起動コマンド、点検実装、時間と再起動上限を明示して渡す。設定DB・Tauri起動口からの組立ては後続であり、現在のPython本番を切り替えない。

## 開始前の点検

`PreflightResources`を既存`ResourceGate`の外側へ渡すと、runnerが実工程を開始する前に点検する。必要なVOICEVOX・Stable Diffusion WebUI・Ollama・Gemini認証・YouTubeトークン・保存領域だけを確認する。チャンネル不一致、空の依存集合、0の期限、不正な起動設定は拒否する。工程を進めながら後で必須サービスを探す形にはしない。

`check`は全不合格の安定コードを返す。認証読取失敗・HTTP異常・容量取得失敗を成功や未設定へ降格しない。資源取得口では先頭の原因コードをrunnerへ返し、全原因は個別にデバッグログへ残す。点検中のキャンセルを検出し、GPUとスリープ抑止の取得にも進まない。

`SystemProbe`はproxyなし・リダイレクトなしの共通HTTP境界でloopbackのIPアドレスだけを読む。VOICEVOXのversion文字列、SDのcheckpointを含むoptions、Ollamaのmodels配列を確認する。HTTPの接続不能だけを未起動と扱い、認証拒否・異常応答・不正JSON・出力上限違反では自動起動へ進まない。URLや応答本文をログへ出さない。ホスト設定はそれぞれ`/version`、`/sdapi/v1/options`、`/api/tags`を指定する。

保存領域は指定した既存ディレクトリに一時ファイルを排他的に作成して閉じ、OSが返した利用者向け空き容量を必要量と比較する。一時ファイルは検査内で削除する。共有・同期ドライブなどの許可は既存StoragePolicyで別途確認する。検査後に他プロセスが容量を使う可能性があるため、実際の書込み失敗も上位へ伝える。

認証は`CredentialProbe`を注入し、対象チャンネルの暗号化保存・有効期限を所有する実装へ委譲する。実装が無いと設定エラーになり、既定成功は用意しない。R3のOAuth更新・本番認証・有料APIをこのWPで受入済みとは扱わない。

## 起動・再起動・終了

起動は明示したローカルサービスに限る。絶対パスの通常ファイルを検証し、シェルを挟まずargvを渡す。ダウンロードやインストールはしない。既に応答するサービスには起動・停止操作を行わない。

`picocast_core::proc::service::OwnedService`が起動時の子ハンドルと専用領域を所有する。Windowsでは停止状態で専用Job Objectへ登録してから再開し、Unixでは専用process groupを使う。共有ポートやPID検索を使って外部プロセスを終了しない。サービスの標準出力・標準エラーはアプリログへ転送しない。

起動には全体の期限を設け、点検ごとの期限、確認間隔、再起動上限も呼出元から渡す。起動待ち中の失敗・Future破棄は局所所有権を破棄して子孫を回収する。成功後の所有権はPreflightへ移し、応答しない自分のサービスだけを上限付きで再起動する。必要に応じて`shutdown`を呼び、所有した全サービスの停止・根の回収を待つ。最後のDropでも専用領域を解放する。起動後の状態異常は、次の事前点検で検出する。

## 検証と受入境界

限定テストは`cargo test --locked -p picocast-pipeline --test preflight`。不足原因の集約、別チャンネル拒否、外部で起動した実プロセスの保護、所有した実プロセスの終了・再起動上限、期限、キャンセル、原因コード保持、資源取得の停止、実ディスク容量と一時ファイル削除、loopback録画応答の形式・容量制限を確認する。

最終確認はローカルの`cargo xtask verify`。2026-10-19時点では実装後の検証待ちである。実VOICEVOX・SD・Ollamaの起動と再起動、実DBの認証読取・期限照合、画面からの操作、macOS実機は未受入。全体のRust作り直し完了や販売可能を意味しない。
