# 旧設定の取り込み

WP-R1-3は `Store::import_legacy_settings` に集約する。オンラインバックアップ済みの絶対パスだけを受け付け、元DBを読取り専用で開く。WAL/SHMの残る入力は拒否する。DBと必要な鍵は事前にリポジトリ外へ退避する。

チャンネル、型付き設定、テンプレート版1、キャラクター、読み辞書と候補、BGM、投稿枠、自動運用、認証情報を1トランザクションで登録する。登録後の値を再読取りして照合し、元DBのSHA-256も前後照合する。未知の設定型・欠損素材・復号失敗・宛先との不一致では全体をロールバックする。元DB全体も新しい鍵で認証暗号化して保持し、未知表・追加列・BLOBを失わない。秘密値を報告へ含めない。

旧暗号はAADなしAES-GCMとして復号し、チャンネルと秘密値種別をAADにした新方式へ再暗号化する。旧鍵が無い場合に新しい鍵を生成しない。新保存先の初期化と鍵作成は呼出側の明示操作とする。

廃止設定の値は暗号化元DBのsnapshotだけに保持し、`legacy:retired_settings:<key>`にはその参照だけを残す。ライセンスキー等の原文を平文AppSettingへ複製しない。`LICENSE_KEY`・`LICENSE_ACTIVATION`は通常のtext型として指定しても拒否し、廃止設定への明示指定だけを許す。元DBの不変・暗号化保持と同入力の冪等性を回帰検査する。

旧テンプレートの複数フィールドと有効状態は `legacy-template-v1` のJSONとして版1の本文へ保持する。WP-R2-2の消費側はこの形式と無効状態を解釈する必要がある。旧API回数上限を金額へ推測変換せず、自動運用を停止・予算0・再承認待ちとして理由と通知を保存する。BGMは元音源を変更せずCASへコピーし、未知の尺には明示測定値を要求する。権利確認は保留として報告する。

DB失敗時にもコピー済みのCAS実体が未参照で残り得る。共有素材を誤削除しないため自動で削除せず、後続の素材管理で照合する。

合成fixtureで全件照合、同入力の冪等性、既存値の非上書き、ロールバック、元DB・音源の不変、暗号既知値、未知表の保持を検証した。CLIは [取り込みと照合](legacy-import.md) に記載する。実DBコピーの受入は未実施であり、WP全体の完了とは扱わない。

2026-10-16の実バックアップ事前照合では、登録済み2チャンネルに所属しないBGM1件・認証情報5件・投稿枠4件を検出した。別チャンネルへの自動転用や削除を行わず、元コピーと鍵を保護する。生成物全体約18.2GBに対し同一ドライブの空きは約18.9GBで、退避とCASへのコピーを同時に保持できないため、全件の実取り込みは未受入。退避先容量と孤立レコードの明示的な移行方針を整えてから実行する。
