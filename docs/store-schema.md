# Rust DB と型付きリポジトリ

WP-R1-2 の実装。実際の保存先は共通 `picocast_core::paths`、SQL と接続は `picocast-store` が所有する。実データの取り込みはこの WP では実行しない。

## 版と移行

- SQLite の `user_version=1` は既存 R0 の3表。`0001_r0.sql` に既存定義を保存する。
- ドメイン全体の初版は `0002_domain.sql`。SQLite の `user_version` は **2** になる。設計書の「ドメインスキーマ v1」と、既存 R0 から連続する移行番号を区別する。
- 空の新規 DB は2本を適用する。台帳がない R0 DB は、SQLite が保存した全 CREATE 文を既知の3表と照合してから移行1の履歴を登録する。未知の追加列・表・index・trigger を持つ DB を自動認証しない。
- `schema_migrations` の番号と SHA-256、`user_version` が一致しなければ接続を中止する。適用済み SQL の変更・履歴の欠落・未来の版を受け入れない。Git の CRLF/LF 変換だけは同一の SQL として扱う。
- 適用前に SQLite のオンラインバックアップを作る。移行は即時トランザクションで排他し、書込み権取得後にも履歴を再検査する。SQL または外部キー検査が失敗したら全変更をロールバックし、バックアップを残す。
- 異常な設定 JSON を空データとして移行しない。元の DB と設定値を残して停止する。バックアップの予約・生成に失敗した場合も移行しない。

## R0 互換と所有境界

`channels.channel_id` を主キーとして保ち、設計上の `id` は同一値を返す生成列にする。既存の `Store::create_channel`・設定・暗号化秘密値 API はそのまま利用できる。`settings` は `channel_settings`、`encrypted_secrets` は `secrets` へ内容を保って移す。秘密値のチャンネルと種類を使う AAD、nonce、暗号文、鍵の版は変えない。

チャンネルの削除 API は `archived_at` を更新する論理削除にする。既存の設定や動画を連鎖削除しない。チャンネル一覧はアーカイブ済みも取得できるが、アーカイブ済みチャンネルのリポジトリを新規取得・再利用してデータを操作することは拒否する。

R0 が持たなかった言語とタイムゾーンは未設定のまま保持し、取り込み時に実設定から埋める。運用元 `operator` の初期値だけは、二重投稿を避けるため `legacy` に固定する。Rust の運用を始めるには運用元の明示的な切り替えが必要になる。

未取得の分析指標・収益と、未計測の費用は NULL / `Option` で保持し、ゼロを捏造しない。CTR は旧版の判定と同じ百分率（例: 8.5% を `8.5`）で保存する。平均視聴率はループ視聴で100%を超えうるため上限を100にしない。

子表にも `channel_id` を持たせ、親との複合外部キーで同じチャンネルを参照させる。例えばシーンを他チャンネルのプロジェクトへ接続したり、QA を別チャンネルの版へ接続したりできない。素材の多相所有者は INSERT/UPDATE と親 DELETE の trigger で検査する。参照中の素材・所有者を消して参照を壊さない。

投稿枠は `channel_id / format / weekday / local_time` を主キーとし、Shorts と Long が同じ曜日・時刻でも別枠として保持する。素材ルートは `StorePaths::assets_directory()` のみに定義し、DB 接続前の危険な保存先検査にも含める。

チャンネルの素材ライブラリは `asset_refs.owner_kind=channel` とし、`owner_id` がその行の `channel_id` と一致することを検査する。旧 BGM は `role=bgm:<旧ID>` として所属を保持し、別チャンネルのライブラリに結び付けない。

旧ネタ履歴の由来が不明な場合は `topics.source=legacy` を保持し、手動提案やトレンド由来として扱わない。

## API

`Store::repository(&ChannelId)` はチャンネルの型付きリポジトリ、`Store::global_repository()` は共有データのリポジトリを返す。各表の構造体と対応する Key 型を使い、`save`・`get`・`list`・`delete` で操作する。チャンネル表のレコードを共有リポジトリへ渡すことは型制約で拒否する。日時は共通 `Timestamp`、JSON は `serde_json::Value`、チャンネルは検証済み `ChannelId` として往復する。

公開 trait は封印されており、外部から SQL の表名・列名を差し込めない。SQL の値はすべて bind する。チャンネルの読み書きは指定された ID に限定し、渡されたレコードの ID が違う場合は書込みを拒否する。

プロジェクト版・テンプレート版・監査履歴は上書きしない。版と監査履歴の削除も拒否する。秘密値は汎用レコードにせず、既存の暗号化 API だけで操作する。移行履歴は型付きの読み取り専用 API `Store::migration_history()` に限定する。

## 検証

`cargo test --locked -p picocast-store --lib` は一時 DB のみを使う。38表すべてを構造体または暗号化/移行専用 API で往復し、SQLite の実表一覧と照合して検査漏れを拒否する。任意値のある列も値を設定して検証する。

既知 R0 からの移行・設定と暗号秘密値の保持・バックアップの旧版復元可能性・移行の冪等性・checksum 改ざん・履歴欠落・未知の R0 構造・失敗時の全体 rollback・チャンネル越境・素材参照・版の上書き拒否を検査する。本番 DB の取り込みと本番切り替えを検証済みとは扱わない。

SHA-256 は RustCrypto の [sha2 0.11.1](https://docs.rs/sha2/0.11.1/sha2/) を固定して利用する。
